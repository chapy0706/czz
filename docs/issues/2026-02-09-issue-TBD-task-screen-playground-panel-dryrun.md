# Issue: Debugパネルを「プレイグラウンド（dry-run）」にして課題画面内で完結させる（#57準拠）

- Source: GitHub Issue #57
- Spec: docs/specs/active/2026-02-09-issue-TBD-task-screen-playground-panel-dryrun.md
- Status: draft
- Owner: TBD
- Updated: 2026-02-10

## 背景 / いま起きていること
- 課題画面に既存の Debug/試用パネルがあり、そこから「実行」を押すと結果画面へ遷移できる。
- 本来は「複数テストケースを倒す前の動作確認」用途なので、結果画面へ遷移せず、課題画面内で完結させたい（#57）。

## 目的（Why）
- Debugパネルを「プレイグラウンド」として扱い、選択した入力とコマンド列で実行し、課題画面内に出力を表示する。
- 配列の見せ方は JSON ではなく、人間が読みやすい数列表示にする。
- 初心者モードはさらに分かりやすく（擬似算数表現など）できる拡張点を用意する。
- 既存の正規フロー（複数テスト評価 → 結果画面遷移）は維持する。

## スコープ（Do）
### 1) 入力（自由入力禁止）
- 入力は任意文字列ではなく、**選択式**にする（悪意ある入力の余地を減らす）。
- UI（例）
  - プリセット選択（昇順/降順/重複/負数/空/1要素/大きめ等）
  - 長さ・値域のスライダー/ステッパー（例：長さ 1〜20、値 -99〜99）
  - 追加オプション（重複を混ぜる、シャッフルする等）
- 生成される入力は **数値配列のみ（当面 1次元）**。
- 入力生成はクライアント側で行い、サーバーには構造化データ（number[]）として渡す。

### 2) 実行（dry-run）
- プレイグラウンド実行は **dry-run** として扱う：
  - `results` に保存しない（永続化しない）
  - `/results` などへ遷移しない
- 実行結果は課題画面内に「プレイグラウンド出力」として表示する。
- 既存の本番フロー（複数テスト評価 → 結果画面遷移）は維持する。

### 3) 表示（全モード共通）
- JSON をそのまま表示しない。
- 数列は `1, 2, 3` のように表示する。
- 失敗時は「短い要約 + 詳細の折りたたみ」。
- 将来の 2次元配列に備え「表形式」の拡張余地（任意）。

### 4) 初心者モードの追加表現（任意）
- 対象コマンドを絞って擬似算数表現を出す（例：MAP_ADD 3 → 各要素に +3）。
- before/after を並べて見せる（差分が一目で分かる）。

## スコープ外（Don’t）
- 任意文字列のCSV入力
- 任意オブジェクト/ネスト構造の入力
- すべてのコマンドを算数表現に翻訳（対象は絞る）
- dsl-core の仕様変更 / DB スキーマ変更

## 受け入れ条件（AC）
- プレイグラウンド実行が結果画面へ遷移しない
- プレイグラウンド実行で results 保存が発生しない
- 入力は選択式で自由入力欄がない
- 入力は number[] のみ（当面）
- 出力は JSON ではなく数列として整形表示される
- 初心者モードで表示ラベル/ヘルプが日本語になり、追加説明を出せる拡張点がある
- 正規 Run（複数テスト評価 → 結果画面遷移）が維持される
- make verify / make evidence 成功 + 引継ぎ4点

## 変更対象（目安）
- `apps/user/app/tasks/[taskId]/page.tsx`
- `apps/user/src/lib/terminal/*`（dry-run 導線、保存/遷移の遮断）
- `apps/user/src/lib/utils/formatOutput.ts`（数列整形。既存があれば統合）
- `apps/user/src/lib/ui-mode/uiModeStore.ts`（初心者向け説明の出し分けに利用）

## 検証
- 目視
  - プレイグラウンドで input を選ぶ（自由入力なし）
  - プレイグラウンド実行 → 課題画面内に出力（遷移しない）
  - 正規 Run → 結果画面遷移 + 複数テストケース結果
- コマンド
  - `make verify`
  - `make evidence`

## UI原則（このペルソナが刺さる形）

### 認知負荷を下げる

- 1画面1目的（「今ここで何ができるか」を先頭で宣言）
- 文字を並べすぎない。重要語だけ太字/ラベル化、説明は折りたたみ
- 失敗が怖い操作（削除など）は、確認ステップ＋結果のフィードバックを必須

### 迷わせない

- 主要操作は右上 or 行末に固定（毎回探さなくていい）
- 成功/失敗/実行中の状態を、文だけでなく視覚でも表す（アイコン/色/トースト）

### “地味にカッコいい”トーン

- 基本は落ち着いたUI（白/グレー基調）
- アクセントカラーは1色（青系など）で統一し、重要アクションにだけ使う
- 危険操作はアクセントとは別の注意色で一貫（ただし警告の煽りは弱め）

### 削除操作の期待値

- 「削除」は怖い。確認ダイアログの文言は短く、結果は即わかる
- 削除実行中はボタンを無効化し、処理中が見える（連打不安を消す）
- 成功したら一覧から消えて、軽い達成感（トーストなど）を出す

## UX で絶対に守ること（非交渉）

### 1) 速度（体感の速さ）

- クリック/タップに即反応（アニメ・押下フィードバック必須）
- ローディングは短く。長いなら「何をしてるか」を見せる（スケルトン等）
- 画面遷移で待たせない。重い処理は段階的に見せる

### 2) 迷わせない（説明より導線）

- 1画面1目的（次に何をすればいいかが1秒で分かる）
- ボタン文言は「行動」が分かる動詞で（例: 「実行する」「ためす」「次へ」）
- 重要ボタンは親指で押しやすい位置（下寄り）に
- 初回は“案内付き”をデフォに（あとでOFFできる）

### 3) 失敗させない（ガードレール）

- 入力ミスは起きる前に防ぐ（プレースホルダ/例/バリデーション）
- エラー表示は責めない。次の一手を必ず提示する
- 「戻る」「やり直す」「スキップ」など逃げ道を用意

### 4) 感情設計（褒める・可愛い・集める）

- 成功時は短く強めに褒める（小さな達成でも）
- 失敗時は“叱らない”。優しくリトライ導線を出す
- マスコットは“助ける存在”（操作や学習を代弁する）
- コレクション要素は「努力の可視化」に直結（例: バッジ/スタンプ/マスコット解放）

## このペルソナに刺さるUIトーン

- かわいい（でも幼稚すぎない）
- 文字量は控えめ、アイコン/図/カードで理解できる
- 状態変化は気持ちいい（押したら反応、成功したらキラッ）
- 失敗の心理コストを下げる（“あなたは悪くない”）

## 代表的なユーザーストーリー

1. スキマ時間（3分）で1問だけ進めたい
2. 迷ったらすぐヒントが欲しい（読まずに分かる）
3. 成功して褒められたい＆可愛い報酬が欲しい
4. 遅い/分からない/失敗が続くと即離脱する

## KPI の例（UX観点）

- 初回起動→1問完了率
- 1セッションあたりの平均操作回数（短く達成できているか）
- 離脱ポイント（ローディング、入力、結果画面）
- ヒント使用率（＝迷いの可視化）

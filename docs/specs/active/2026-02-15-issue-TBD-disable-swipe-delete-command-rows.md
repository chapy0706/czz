# Spec: コマンド行の左右スワイプ削除を無効化（誤爆防止 / タップ編集に集約）

- Issue: TBD
- Status: active
- Updated: 2026-02-15
- Owner: TBD

## Goal（勝利条件）

コマンド操作の誤爆（意図しない削除）を防ぐため、コマンド行の操作を次に固定する。

- タップ/クリック: 編集画面へ進む（維持）
- 左右スワイプ: **無効化**（削除は発火しない / UIも出さない）

## 背景

- 課題画面では「スワイプ削除」を入れる案があったが、タッチ端末ではスクロール・フリックと誤判定しやすく、学習中の心理安全性を下げる。
- コマンドはユーザーの思考そのもの（積み上げ）なので、誤削除はダメージが大きい。
- 操作は少ないほど良いが、「壊れない」ほうが優先。

## Non-goals（やらないこと）

- コマンド行タップで編集する導線の変更
- DSL 実行/評価ロジック、API、DB の変更
- 課題画面の他のボタン整理（別Issueの範囲）

## Scope（変更対象の当たり）

- Command Builder（コマンド一覧）
  - `apps/user/src/lib/command-builder/CommandRow.tsx`
  - `apps/user/src/lib/command-builder/useSwipeActions.ts`（存在する場合）
  - `apps/user/src/lib/command-builder/CommandList.tsx`
  - `apps/user/src/lib/command-builder/CommandBuilder.tsx`

- E2E（該当があれば更新）
  - `e2e/tests/command-builder-*.spec.ts`

## 仕様詳細

### 1) 左右スワイプを「無効化」する

- コマンド行に対して、左右スワイプで削除が起きないこと
- スワイプに伴う「削除アニメーション」「削除のUI（背景/アイコン/ラベル）」が出ないこと
- 画面スクロールは妨げないこと（縦スクロール優先）

実装方針（推奨）:
- 「削除」のために追加した gesture / pointer handlers がある場合、削除発火パスを削除する
- 既存で pointer handlers が必要な事情がある場合は、左右方向の処理を無効化し、クリック判定のみ残す
- 可能なら「スワイプに関する状態（dragX等）」自体を削除し、不要な re-render を避ける

### 2) タップ/クリック編集は維持

- コマンド行のタップ/クリックで編集 UI（Sheet/Drawer等）が開く
- ドラッグ/スワイプの入力があっても編集が誤発火しない（クリックとドラッグの競合が無い）

### 3) 削除の導線（最低限の安全策）

左右スワイプを無効化した結果、削除導線が失われる場合は、誤爆しにくい場所へ移す。

- 推奨: 編集画面（CommandEditor）内に「削除」ボタンを配置
  - 押下時は確認（Dialog）を出す
  - もしくは Undo をトーストで提供（どちらかは必須）
- 画面上（一覧）に常時「削除」ボタンを復活させるのは避ける（ノイズ増のため）

※ すでに別導線が存在している場合は、その導線を維持してよい。

## Acceptance Criteria（受け入れ条件）

- コマンド行を左右にスワイプしても、コマンドが削除されない
- 左右スワイプに関連する削除UIが表示されない
- 縦スクロールが自然に動作し、引っかかりがない
- コマンド行タップ/クリックで編集UIが開く
- （削除導線が無くなる場合）編集画面内に「削除」＋確認 or Undo がある
- E2E が更新され、`make verify` が通る

## Implementation Plan（最小ステップ）

1) コマンド行で左右スワイプ削除がどこで実装されているか特定
2) 削除発火パスと関連UIを削除/無効化
3) タップ/クリック編集の動作確認（競合がないこと）
4) 削除導線が不足する場合は、編集画面内に「削除」＋確認/Undo を実装
5) E2E 更新
6) `make verify` → `make evidence`

## Test Plan（証拠）

- 手動:

  - 縦スクロールが妨げられない
  - 行タップで編集が開く
- 自動:
  - `make verify`
  - `make evidence`
  - 可能ならE2Eで「左右ドラッグしても行数が減らない」ことを検証

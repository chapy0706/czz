# Spec: プレイグラウンドをデフォルト折り畳み（アコーディオンで詳細表示）

- Issue: TBD
- Status: active
- Updated: 2026-02-15
- Owner: TBD

## Goal（勝利条件）

プレイグラウンド（右側パネル/詳細パネル）が常時表示だとノイズになるため、**基本は折り畳み表示**にし、ユーザーが必要なときだけ展開できるようにする。

- デフォルト: 折り畳み（collapsed）
- 「プレイグラウンドの詳細へ」ボタン（または同等の導線）を押すと、アコーディオンとして展開され、全体が見える

## 背景

- 課題画面は思考（コマンド構築）に集中させたいが、常時表示の情報量が多いと集中が途切れる。
- “必要なときだけ開ける” は UX の基本。特に初心者モードでは効果が大きい。

## Non-goals（やらないこと）

- DSL実行/評価ロジックの変更（`packages/dsl-core` / UseCase）
- API/DB の変更
- プレイグラウンドの内容自体の再設計（項目追加・削除の大改造）
- 初心者/上級者モードの概念変更（表示条件の追加は許容だが、モード仕様は変えない）

## Scope（変更対象の当たり）

最終確定は /codex 探索でよいが、当たりは以下。

- 課題画面のレイアウト/右側パネル
  - `apps/user/app/tasks/[taskId]/page.tsx`
  - `apps/user/src/components/playground/**`（存在する場合）
  - `apps/user/src/lib/playground/**`（存在する場合）

- UIコンポーネント（Accordion / Panel / Button）
  - `apps/user/src/components/ui/accordion.tsx`（shadcn/uiの可能性）
  - 既存のパネル/アコーディオンがあればそれを流用（新規導入は最小）

- E2E
  - `e2e/tests/pipeline-panel.spec.ts`（プレイグラウンドが絡む可能性）
  - `e2e/tests/*playground*.spec.ts`（存在する場合）

## 仕様詳細

### 1) 初期状態（デフォルト）

- 課題画面を開いた直後、プレイグラウンドは折り畳まれている
- 折り畳み時は **見出し行（ヘッダー）だけ**表示される
  - 見出し例: 「プレイグラウンド」
  - 状態が分かるアイコン（chevron）などは任意（既存UIに合わせる）

### 2) 展開導線（ボタンで開く）

- 画面上に「プレイグラウンドの詳細へ」（文言は仮、既存用語に合わせてよい）ボタンを配置
- ボタンを押すと、プレイグラウンドがアコーディオン展開され、全体が見える

補足:
- ボタンの配置場所は “ノイズが増えない場所” を優先（例: 右側パネルのヘッダー、またはコマンドライン周辺の小さな導線）
- アコーディオンは「展開/折り畳み」をトグルできること

### 3) 展開時の挙動

- 展開時は、既存のプレイグラウンド内容がそのまま見える（UI要素は移動しない）
- 展開に伴ってレイアウトが崩れない（スマホ幅含む）

### 4) 状態保持（推奨）

- 同一セッション内での操作の快適性のため、展開状態は保持してよい
  - 推奨: URLクエリに持たない（共有で混乱するため）
  - 推奨: Zustand / localStorage などの軽い永続化（どちらでも良い）
- ただし、まずは “デフォルト折り畳み” の実現を優先し、状態保持は後回しでも良い

### 5) 初心者/上級者モードとの関係

- 両モードで「デフォルト折り畳み」は同じにする（統一）
- ただし、初心者モードではボタン文言や補助説明（tooltipなど）を付けても良い

## Acceptance Criteria（受け入れ条件）

- 課題画面ロード直後、プレイグラウンドは折り畳まれている
- 「プレイグラウンドの詳細へ」ボタン（または同等の導線）で展開でき、全体が見える
- 展開/折り畳みのトグルが可能
- 既存の操作（コマンド編集、ためす/チェック等）が壊れない
- 既存E2Eが意図に合わせて更新され、`make verify` が通る

## リスクと対策（NFR）

- 安全性: 状態管理の増加でバグ → 単一の state（isOpen）に絞る、境界を狭める
- 変更容易性: レイアウトが密結合 → 「プレイグラウンド本体」と「開閉UI」を分離
- 性能: 展開時だけ重い処理がある場合 → 折り畳み時は描画しない（条件レンダリング）を検討
- 運用: E2Eが壊れやすい → data-testid を必要最小限で付ける

## Implementation Plan（最小ステップ）

1) プレイグラウンドがどのコンポーネントで常時表示されているか特定
2) アコーディオンの “開閉state” を導入し、デフォルト closed にする
3) 「詳細へ」ボタン（またはヘッダークリック）で open にできる導線を追加
4) 折り畳み時は内容を描画しない/最小化（必要なら）
5) E2E更新（初期は閉、ボタン押下で開、を検証）
6) `make verify` → `make evidence`

## Test Plan（証拠）

- 手動:
  - 初期は閉じている
  - ボタンで開閉できる
  - スマホ幅でも崩れない
- 自動:
  - `make verify`
  - `make evidence`
  - E2E: 初期閉 + ボタンで開いて中身が見える

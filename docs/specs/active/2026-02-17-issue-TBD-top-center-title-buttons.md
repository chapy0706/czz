# Spec: TOP画面のタイトルとボタン類を中央寄せにする（パネルは現状維持）

- Issue: TBD
- Status: draft
- Owner: chapy
- Updated: 2026-02-17

## Goal
TOP画面で、タイトルと主要ボタン群を中央寄せにし、視認性と操作性を上げる。一方で、マスコットパネルとユーザーアカウントパネルは現状の位置・寄せ方を維持する。

## Non-goals
- TOP以外の画面レイアウト変更
- マスコットパネル / ユーザーアカウントパネルのUI変更
- コンテンツ追加、文言変更、配色刷新

## 対象範囲（UI要素）
### 中央寄せにしたい
- タイトル（アプリ名/見出し）
- 主要ボタン類（例: 「はじめる」「課題一覧へ」等、TOPの主要CTA）

### 中央寄せにしない（現状維持）
- 動物マスコットのパネル（既存の左寄りなどを維持）
- ユーザーアカウントのパネル（既存の位置・寄せ方を維持）

## 仕様（振る舞い）
- TOP画面のタイトルと主要ボタン群を同一の「中央寄せコンテナ」に入れる。
- マスコットパネルとユーザーアカウントパネルは、中央寄せコンテナの外に残す（または既存レイアウトを保ったまま）。
- レスポンシブ（スマホ幅）で、中央寄せが崩れないこと。
- 既存のクリック領域やナビゲーションが変わらないこと（レイアウトの変更でボタンが押しづらくならない）。

## 調査の当たり（候補ファイル）
まず TOP画面の実体を確定する。

- `apps/user/app/page.tsx`
- `apps/user/app/(...)/page.tsx`（ルート構成次第）
- TOP画面で使っているコンポーネント
  - 例: `apps/user/src/components/.../Top*`
  - 例: `apps/user/src/components/.../Home*`

探索例:
- `rg -n "export default function.*Page|function Home|TOP|トップ|はじめる" apps/user/app`
- `rg -n "mascot|studying\.gif|account|user" apps/user`

## Implementation Plan（最小ステップ）
1. TOP画面のファイルと、タイトル/ボタン群/各パネルのDOM位置を特定する
2. タイトル + 主要ボタン群だけを包む中央寄せコンテナを導入する
   - 例: `mx-auto` / `text-center` / `items-center` / `justify-center`（Tailwind前提）
3. マスコットパネルとユーザーアカウントパネルが中央寄せの影響を受けないことを確認する
   - 位置が変わった場合は、コンテナ分割または既存のレイアウト制約を復元する
4. スマホ幅とデスクトップ幅で表示を確認する（最低でも2ブレークポイント）
5. make verify → make evidence

## Acceptance Criteria（受け入れ条件）
- TOP画面で
  - タイトルが中央寄せになっている
  - 主要ボタン群が中央寄せになっている（ボタン群全体が中央にまとまって見える）
- マスコットパネルとユーザーアカウントパネルは
  - 位置が変わらない（見た目として「今のまま」）
  - 寄せ方も変わらない（中央寄せの影響を受けない）
- 既存のボタン押下や導線が壊れていない
- make verify / make evidence が成功する

## NFR（4軸チェック）
- 安全性: 表示のみ。権限/データ取得/外部通信を増やさない。
- 変更容易性: 中央寄せ対象をコンテナで限定し、他要素への副作用を減らす。
- 性能: DOM構造の軽微変更のみ。不要な再レンダリングを増やさない。
- 運用: 変更ファイルを最小化し、evidenceログで再現可能にする。

## Test Plan
- 手動:
  - スマホ幅で、タイトル/ボタン群が中央寄せ、パネル2つが現状維持であること
  - デスクトップ幅で同様に確認
- 自動:
  - make verify
  - make evidence
